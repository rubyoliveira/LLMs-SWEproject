ACTIVITY 2: REQUIREMENT DECOMPOSITION & GITHUB ISSUES

The product scope was decomposed into three primary user-facing epics highlighting our core LLM and deterministic tool integration. Each story has been converted into trackable GitHub repository issues with formal acceptance criteria.

GitHub Issue #1: Point-of-Sale Card Multiplier & Benefit Routing Engine

User Story: As an Optimizer cardholder with multiple cards, I want the co-pilot to parse my real-time purchase query and identify the best card, so that I maximize point multipliers and never let monthly statement credits expire unused. 
ACCEPTANCE CRITERIA (GHERKIN FORMAT):
AC 1.1: Given an unstructured merchant string (e.g., "Lunch at Shake Shack"), 
        the LLM must call `resolve_mcc` and return valid category code `5814` 
        (Fast Casual Dining) with >= 90% accuracy.

AC 1.2: Given registered cards in the user wallet, the system must 
        deterministically rank cards by net yield (multiplier + unredeemed 
        monthly statement credits).

AC 1.3: Given unspent credits expiring within 7 days, the response must 
        explicitly alert the user to apply the perk and deduct it from the net charge.

GitHub Issue #2: "Treat-It-Like-Debit" Safe-Spend & Utilization Guardrail

User Story: As a First-Time credit card user, I want the system to check my transaction against my checking balance and credit limit, so that I avoid debt, pay zero interest, and maintain credit utilization below 10%. 
ACCEPTANCE CRITERIA:
AC 2.1: Given purchase amount $P$, checking balance $C$, and card limit $L$, 
        if $P > C$, the co-pilot must return a strict warning that funds are 
        insufficient for debit-parity.

AC 2.2: If $(P + \text{current\_balance}) / L > 0.10$, the system must calculate 
        the exact mid-cycle payment needed to keep statement utilization below 10%.

AC 2.3: All numeric figures in the LLM response must be verified against 
        `calculate_safe_spend()` tool output with 0% arithmetic hallucination.

GitHub Issue #3: Thin-File Starter Card Evaluator & Jargon Demystifier

User Story: As a college student with no credit score, I want unbiased recommendations for starter cards based on my actual cash flow, so that I can establish credit without predatory annual fees or denied applications. 
ACCEPTANCE CRITERIA:
AC 3.1: Given income, student status, and banking history, the system recommends 
        1–2 high-approval starter cards (e.g., Discover it Student, Chase Freedom Rise) 
        without affiliate ranking bias.

AC 3.2: When queried about billing terms ("statement vs current balance"), the system 
        provides plain English definitions with zero technical jargon.

ACTIVITY 3: AI-ASSISTED TEST-DRIVEN DEVELOPMENT (TDD)

In accordance with TDD principles, complete pytest and vitest test suites covering unit, integration, and guardrail logic were generated and refined prior to final implementation.

1. Test Suite Architecture & Failure-to-Pass Verification

Test File Target Functionality Edge Cases Tested Initial Red State (Confirmed Failure)
test_mcc_resolver.py Unstructured merchant string parsing via LLM function calling Ambiguous Square merchants, delivery apps (Grubhub vs DoorDash), retail grocery combos Failed: Mock returned generic retail for Square dining tags; failed to parse MCC 5814.
test_safe_spend.py Deterministic utilization and debit-parity calculator Purchase exceeding checking; balance exceeding 10% utilization limit; floating point cents Failed: Zero-division error on uninitialized credit limit; float rounding errors.
test_perk_tracker.py Expiring card statement credit evaluation Perk already redeemed; perk expiring in 2 days vs 20 days; multiple active perks Failed: Duplicate perk application logic on multi-swipe sessions allowed negative balance.
test_guardrail_eval.py Pydantic schema assertion on output payloads Missing recommended card field; non-deterministic math hallucination check Failed: Unstructured text response failed Pydantic V2 validator; missed non-card queries.

2. TDD Implementation Workflow

  1. Red Phase (Tests Written First): Automated test suites defined assertions across 6 core domains. Executed prior to backend logic completion, confirming immediate failure.
  2. AI-Assisted Inspection: Edge cases (e.g., leap-year February 29th statement dates, CARD Act weekend payment rollovers, negative balance bureau reporting) were generated via LLM prompt evaluation and manually audited.
  3. Green Phase (Production Implementation): Endpoints and deterministic calculation modules written to satisfy schemas, bringing test pass rate to 100%.
